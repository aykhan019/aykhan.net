KC2: indirect C2 over npm dist-tags

KC2 is an educational, defensive-security lab for studying how mutable npm dist-tags can be abused as an indirect command-and-control mailbox—and how defenders can detect the resulting artifacts.

Authorized research only

Overview

Published npm package versions are immutable: once 1.0.0 exists, it cannot be republished with different contents. Dist-tags are different: they are mutable pointers to published versions. KC2 uses one operator-owned, disposable public package as a mailbox. Its message-bearing tags always point to the fixed 1.0.0 version; only the metadata changes.

The operator CLI writes command tags. The lab agent polls the package’s tag map, runs a validated allowlisted mock operation, then writes result tags. Neither side opens a connection to the other. This is deliberately slow, visible, constrained, and valuable for detection research.

Immutable content

Package files and version history remain untouched after the initial publish.

Mutable metadata

Dist-tag names carry plain base64url JSON while their values remain 1.0.0.

Observable channel

Public tags are world-readable and leave registry, proxy, and endpoint artifacts.

How it works

  1. The agent publishes one stable x-ann-* announcement for historical discovery.
  2. The CLI writes a direct x-cmd-<agentId>-* tag or a single x-cmd-all-* broadcast tag.
  3. The agent reads dist-tags on its polling interval, validates and deduplicates the task, then publishes x-res-* result tags.
  4. The CLI’s background poll reassembles results and prints asynchronous notifications.

The announcement is not a heartbeat. A discovered agent is historically known, not proven online; host data, leases, and liveness state are intentionally absent.

Features

Protocol & transport

Base64url JSON in tag names, chunking, stable announcements, direct/broadcast tasking, cleanup, retry, and post-write verification.

Reliable by design

Monotonic sequences, per-target deduplication, atomic state, malformed-tag skipping, and at-most-once execution.

Defender-ready

Deliberately analyzable payloads, known user agent, detection queries, rules, and observable registry churn.

All KC2 tags point to a version that already exists. Chunk reassembly waits until every numbered part is present. Direct command tags are removed after processing; broadcast tags remain so other polling agents can receive the same task. Cleanup removes only KC2 command, result, and announcement tags—it never changes package versions.

Quick start

Before you begin

Use Node.js 22+, an npm account, a public disposable package you own, and a granular short-lived token restricted to that package. The KC2 repository itself is private and is never published as the mailbox package.

Public-package dist-tags and their payloads are visible to anyone. Public registry use requires explicit opt-in. Put tokens in owner-readable-only env.sh on POSIX systems or in NPM_C2_TOKEN, never in config.json.

Explicit opt-in operations

geolocate is disabled unless enableGeolocate=true. exec <command> [args...] is disabled unless enableExec=true and uses an argument array without shell parsing. Desktop actions—openurl, say, notify, beep, bounce, volume <0-100>, rickroll, and party—require enableFunOps=true and are only appropriate for an attended, authorized lab host.

Protocol and reliability

  • Agent IDs use letters, digits, and underscores; sequences are positive and allocated monotonically.
  • Payloads are unpadded base64url JSON. npm caps tag names at 214 characters, so larger data uses numbered chunks.
  • State is written atomically. The victim tracks processed sequences before publishing a result, prioritizing at-most-once execution over guaranteed result delivery.
  • A new or upgraded agent baselines existing command sequences before processing new work. Malformed tags are logged and skipped.
  • Registry writes are serialized. Post-write reads re-publish chunks silently dropped by registry contention; transient failures use bounded exponential backoff.

Operations

Preflight and state

Confirm Node.js 22+, run the project checks, use one disposable owner-controlled package, and use a short-lived package-scoped token. Keep risky opt-ins disabled unless an authorized exercise requires them. Runtime state includes victim-state.json, attacker-state.json, chains.json, optional logs, and received files.

Back up both state files and chains.json1.0.0 placeholder version. For upgrades, stop processes, back up state, review protocol/configuration changes, run checks, start the victim then attacker, and verify one ping. Roll back with the matching pre-upgrade state and recorded tag set.

Detection engineering

Detection is a first-class purpose of this lab. Tune every example to local telemetry and validate false positives before relying on it.

  • x-cmd-*, x-res-*, and x-ann-* prefixes; base64url-like tag names and 1of2 chunk patterns.
  • High dist-tag churn without version publishing; repeated dist-tag GET polling; PUT and DELETE activity on dist-tag endpoints.
  • KC2’s KC2/1.0 (educational research) user agent, long-running Node polling processes, and local state files.
  • When explicitly enabled: Wi-Fi scan utilities followed by WPS lookup behavior.

Security boundaries and ethical use

Important safety boundary

KC2’s controls reduce accidental exposure; they do not make this channel safe for covert production use. Never use a real production package as the mailbox.

  • Use only systems, registries, accounts, and packages you own or have explicit authorization to test.
  • Use a dedicated unprivileged lab account and directory. Paths are not restricted to a sandbox root.
  • Keep revealEnv, enableFunOps, enableGeolocate, enableExec, and insecure HTTP disabled unless an authorized exercise specifically needs them.
  • Never commit env.sh, tokens, captured data, or private registry URLs. Rotate a potentially exposed token immediately.
  • There is no persistence, privilege escalation, obfuscation, encryption, credential theft, screen capture, or cloud upload. Payloads are intentionally plain base64url.

Project structure

KC2 has zero runtime npm dependencies and uses the Node.js standard library. It includes source linting, a test suite with an 80% coverage threshold, and the MIT license.

FAQ and troubleshooting

SymptomSafe response
HTTP 401/403Verify package scope and token permissions. Revoke suspect credentials and issue a new short-lived package-scoped token.
HTTP 404Check registry URL, package name, and that the package has an initial 1.0.0 version.
Timeout or 5xxCheck registry health and network policy; keep retries bounded rather than raising them without limit.
Incomplete resultInspect tag limits and write contention. Because execution is at-most-once, repeat only a task known safe to repeat.
Cleanup blocked by 2FAUse interactive npm dist-tag rm for the lab package; never weaken a production package policy.
Corrupt stateStartup fails closed. Preserve the file, then restore the matching backup or reset the disposable lab.
Unexpected tags or tasksStop both processes, revoke the token, preserve relevant artifacts, and investigate before cleanup.
